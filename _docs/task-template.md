# Task template

Use this structure when grooming a GitHub issue. Replace the placeholders with concrete, task-specific content.

## Goal

One or two sentences describing what should be true when the task is complete.

## Acceptance criteria

- [ ] Checkable statement
- [ ] Checkable statement
- [ ] Include relevant edge cases

## Out of scope

- Explicitly state what this task does not include.
- If something was moved to another task, link the follow-up GitHub issue.

## Constraints

- Files/components that should be changed or avoided
- Libraries/dependencies that should or should not be used
- Existing architectural decisions
- Relevant project guidelines/documents
